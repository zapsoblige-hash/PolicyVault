# PolicyVault covenant spec — v0.4.1 (standardness redesign)

Status: VM-VERIFIED + PRODUCTION-BYTE-SCANNER-VERIFIED + TESTNET-VERIFIED
(below-threshold agentSpend standardness path on a default node). Additive
over the frozen v0.4; **v0.4 is never mutated**. Mainnet remains gate R.

Source: `contracts/PolicyVault.v0.4.1.sil`
(SHA256 `421bfed824cf66a9e989f90c5b86fc7359faa070a5d94aace3c325f35ad1da4e`),
regenerated byte-identically by `tools/gen_v4_1.js`. Version tag
`policyvault-0.4.1`.

## 1. Why v0.4.1 exists

The frozen v0.4 covenant redeem script carries **18 static `OpCheckSig`
opcodes**. Kaspa's default mempool standardness check
(`rusty-kaspa mining/src/mempool/check_transaction_standard.rs`) counts static
P2SH sig-ops with `post_toccata_p2sh_sig_scanner` and rejects any P2SH input
whose redeem script exceeds `MAX_STANDARD_P2SH_SIG_OPS = 15`. So every v0.4
covenant spend is **non-standard** and a default node refuses to relay it
(observed live in Checkpoint H; see `docs/v04-h-standardness-finding.md`). v0.4
remains consensus-valid but unrelayable without `accept_non_standard`.

v0.4.1 fixes this **at the covenant layer** by consolidating the six
non-terminal owner operations behind one entrypoint, cutting the static sig-op
count from 18 to **13** (`<= 15`, with 2 sig-ops of headroom).

## 2. What changed (and what did NOT)

Changed — owner operations only:

- The six non-terminal owner entrypoints of v0.4 (`ownerSetAgentRoot`,
  `ownerSetApprovers`, `ownerTopUp`, `ownerTopUpReserve`, `ownerPause`,
  `ownerUnpause`), each of which carried its own `checkSig(ownerSig, owner)`,
  are replaced by **one** entrypoint:

  ```
  ownerControl(State prevState, State newState, int opSelector, sig ownerSig)
  ```

  with **exactly one** `require(checkSig(ownerSig, owner))` and an internal
  nested `if/else` dispatch to six mutually-exclusive rule sets selected by
  `opSelector`:

  | opSelector | operation        | rule set (successor vs predecessor)                                  |
  |-----------:|------------------|----------------------------------------------------------------------|
  | 0          | setAgentRoot     | agentRoot replaced; policyNonce +1; all else preserved               |
  | 1          | setApprovers     | approver slots + approvalM replaced (A2 distinctness, 1≤M≤active); policyNonce +1; boundVaultId/protected/feeReserve/paused/agentRoot preserved |
  | 2          | topUp            | protectedValue strictly increases; feeReserve/boundVaultId/paused/agentRoot preserved; approvers preserved; nonce preserved |
  | 3          | topUpReserve     | feeReserve strictly increases; protectedValue/boundVaultId/paused/agentRoot preserved; approvers preserved; nonce preserved |
  | 4          | pause            | prev.paused==0, new.paused==1; all else preserved                    |
  | 5          | unpause          | prev.paused==1, new.paused==0; all else preserved                    |

Static sig-op accounting (whole redeem script, counted regardless of branch):

```
agentSpend:  1 (agent) + 10 (approver slots)   = 11
ownerControl:                    1 (owner)      =  1
ownerRecover:                    1 (owner)      =  1
                                                 --
                                        total     13   (<= 15)
```

NOT changed — byte-identical to v0.4:

- **State layout**: 441-byte region, 17 mutable fields, exact field order
  `boundVaultId, protectedValue, feeReserve, paused, agentRoot, approver1..10,
  approvalM, policyNonce` = 12×33 + 5×9 = 441 (verified field-by-field from the
  compiled script with a uniquely-patterned state).
- Agent leaf (124-byte preimage, domain `0x50563401`), agent tree depth ≤ 12,
  unspendable padding leaf `SHA256(0x50563400)`.
- Recipient leaf `SHA256(0x50563301 ‖ xonly)`, recipient tree depth ≤ 16.
- 10 approver slots, per-agent fee cap, fee-reserve conservation model
  (`reserveConsumed = prev.feeReserve − new.feeReserve`, `0 ≤ reserveConsumed
  ≤ agentMaxFeePerTx` and `≤ actual fee`), principal conservation
  (`new.protectedValue = prev.protectedValue − payAmount`), exact
  successor-value pin, singleton successor uniqueness.
- `agentSpend` and `ownerRecover` entrypoints and their call ABIs.

Because the state layout, constructor args, and templating anchors are
identical, the SDK reuses the same state/merkle/approval/compiler machinery
across v0.4 and v0.4.1; only the covenant path, version tag, artifact build
dir, and the owner-op encoder call shape differ.

## 3. Redeem size and budgets (measured on the compiled covenant)

- Redeem script: **16,980 bytes** (v0.4: 18,839).
- Worst-case priced compute budget (agent depth 12 + recipient depth 16 +
  10-of-10 approvals + reserve): **1,306,977 script units → budget 131**.
  Owner ops ≈ 21–22; `ownerControl` setApprovers (10 approver checkSigs on the
  heaviest branch) ≈ 22; `ownerRecover` ≈ 14. Peak stack ≤ `MAX_STACK_SIZE`
  244. (Per-branch execution is unchanged from v0.4; only the *static* opcode
  count dropped.)

## 4. opSelector / sighash security

`opSelector` is a **call argument** and is NOT committed by `SIG_HASH_ALL`
(v1 sighash commits outputs/outpoints/sequences/signed-input UTXO/lockTime/
subnetwork/gas/payload/hashtype — not signature scripts and not call args). A
malicious delegate could therefore swap the selector after the owner signs.
This cannot authorize a different successor because:

1. The **successor state IS committed** — it is the covenant output's
   scriptPubKey (P2SH of the compiled successor), which `SIG_HASH_ALL` commits.
2. The six branches are **mutually exclusive** and each pins exactly the fields
   its operation may change and requires every other field preserved. A
   successor that is valid under selector *X* violates at least one field rule
   of every other selector *Y*, so a swapped selector **rejects**.
3. `require(opSelector >= 0)` and `require(opSelector <= 5)` bound the selector;
   the final `else` (unpause) is reachable **only** by selector 5. Without the
   upper bound, selector ≥ 6 on a paused vault would fall through to unpause —
   so the bound is load-bearing and is proven sensitive (§6).

Proven by cross-selector swap tests at both the VM layer
(`tests/vm/tests/v4_1_production.rs`) and the production-encoder byte layer
(`tests/vm/tests/v4_1_encoder_integration.rs`).

## 5. Recovery isolation

`ownerRecover(State prevState, State[] nextStates, sig ownerSig)` remains a
**separate terminal break-glass** entrypoint with its own
`require(checkSig(ownerSig, owner))` and recovery-mode parsing. It carries no
`opSelector` and produces no covenant successor. The production encoder rejects
a recover call that carries a selector (control-as-recover) and an
`ownerControl` call that lacks a successor (recover-as-control).

## 7. Version boundary / fail-closed

`policyvault-0.4.1` is dispatched explicitly at every layer (covenant selector,
`pv_call_encoder`, SDK compiler/builder/finalizer, manifest, request, submit,
reconcile). Unknown versions FAIL CLOSED with no default and no cross-version
fallback. A v0.4 manifest is never auto-upgraded to v0.4.1; the two have
distinct state identities (the version is folded into the stateId), so their
build dirs and manifests never collide.
