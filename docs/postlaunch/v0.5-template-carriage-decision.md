Status: **EXPERIMENT COMPLETE. DESIGN FREEZE DECLARED BY THE OWNER
(2026-09-01) — see `v0.5-design-freeze.md`.** Frozen carriage name:
**TRANSACTION-DERIVED VERIFIED TEMPLATE CARRIAGE** (Variant C below).
Terminology rule (owner): Variant C is NEVER canonically called
"argument-supplied" — that name belongs to Variant B (caller-supplied
bytes). Disposition: C = FROZEN DESIGN; B-lean = proven FALLBACK only;

production financial behavior, and the x402/later programs are
untouched. Original directive: "RESOLVE TEMPLATE-CARRIAGE DECISION

Evidence: `tests/vm/tests/v5_experiment_token_template_carriage.rs`
(6 tests, real TxScriptEngine, covenants enabled, real Schnorr

## 0. Result in one paragraph

Argument-supplied template carriage preserves every VM-PROVEN security
property of the baked-in design and is materially cheaper — and the
implementation surfaced a strictly better sub-variant: the accepted
template already rides the transaction ONCE inside the token input's
own P2SH redeem, and the upstream `readInputStateWithTemplate` builtin
proves those exact bytes (blake2b hash AND P2SH commitment) before any
state is trusted, so the controller can slice the proven prefix/suffix
out of the token input's sigscript using its PINNED geometry and never
carry the template itself, with **no interface change at all**.
Measured at the v0.5 target shape (family bound 2): controller compute
−40 %, transaction bytes −65 %, minimum relay fee −65 %, controller
sigscript constant at 1,156 B regardless of template size.
**Recommendation (accepted by the owner as the freeze): variant C —
TRANSACTION-DERIVED VERIFIED TEMPLATE CARRIAGE.** Descriptor schema:
NO change. The carriage decision is resolved cleanly; with it, v0.5 is
**DESIGN-FREEZE-READY** (freeze not declared — owner gate).

## 1. The variants compared (identical transaction/policy shapes)

| | Where the accepted template's prefix/suffix bytes come from | Controller pins | Call interface |
|---|---|---|---|
| **A baked-in** (D1, `V5TokenControllerProbe.sil`) | constructor constants inside the controller redeem | covid + hash + geometry + **bytes** | `newState, sig, selfNew, recipientNew` |
| **B arg** (`V5TokenControllerProbeArgTemplate.sil`) | caller pushes them as two call arguments; explicit up-front geometry + blake2b gate; builtins re-verify at use | covid + hash + geometry | A's args **+ `templatePrefix`, `templateSuffix`** |
| **B-lean** (`…ArgTemplateLean.sil`) | as B without the up-front hash (geometry gate only; hash verified by the builtins at every use) | covid + hash + geometry | as B |
| **C tx-derived** (`V5TokenControllerProbeTxTemplate.sil`) | sliced from the token INPUT's revealed redeem AFTER `readInputStateWithTemplate` proved them (hash + P2SH) | covid + hash + geometry (prefix/state/suffix lengths) | **identical to A** |

Both bindings are unchanged in every variant: BINDING A (pinned
`kcc20Covid`, family enumeration by covenant id, exact family counts)
and BINDING B (hash + P2SH verified input template; hash-verified
reconstruction of both continuation outputs). Token-value and KAS-fee
domains stay separate (the controller's KAS is exactly preserved across
a token spend). Nothing external (indexer/server/UI/descriptor label)
participates at the financial boundary.

**Why the baked-in controller was so large (SOURCE + VM evidence):**
the KCC20 example template at bound 2 is only 1 + 46 + 1,521 bytes
(prefix/state/suffix), but the silverscript compiler inlines constant
byte arrays at every use site — the two
`validateOutputStateWithTemplate` calls each reference prefix and
suffix twice (hash check + reconstruction), so the D1 controller
redeem embeds **four verbatim copies** of the template
(asserted by the probe: 4 copies at every bound; 0 for B/B-lean/C).
That, not "the pinned template size", is the scaling driver.

## 2. Measurements (real engine, production pricing model)

Pricing/mass model, SOURCE-VERIFIED in rusty-kaspa v2.0.1 (the exact
tree the production kaspad is built from): pushed bytes 1 unit/byte;
blake2b 2 units/byte; sig-op = `mass_per_sig_op` 1000 grams = 100,000
units; 1 budget unit = 10,000 units = 100 grams; compute mass = tx bytes
× 1 + output SPK bytes × 10 + 100 × Σ committed budgets; transient mass =
tx bytes × 4, normalized by 500,000/1,000,000; fee mass =
max(compute, normalized transient); minimum relay fee =
`DEFAULT_MINIMUM_RELAY_TRANSACTION_FEE` 100,000 sompi/kg = **100
sompi/gram post-Toccata** (node-configurable via `--minrelaytxfee`).
Compute budgets are committed per input via
`ComputeBudget::checked_covering_script_units` BEFORE signing (they are
sighash-covered), then re-executed — the harness proves units do not
depend on the committed budget.

## 4. New attack surface found (and closed)

- **Split-point malleability of the in-VM hash.** The builtins verify
  `blake2b(prefix || suffix)` with NO length framing, so moving bytes
  across the prefix/suffix split leaves the hash unchanged (proven as a
  pure fact for shifts 1/7/64 and exercised in the VM). A caller-supplied
  carriage therefore MUST pin the geometry (prefix/suffix lengths) next to
  the hash — B does, and every shift is refused. This is also the exact
  reason KCC-0001's BLAKE3 identity frames each part with LE64 lengths;
  the descriptor's separate-hash discipline stands. A and C are
  unaffected (no caller-controlled split), but their geometry is pinned
  anyway.
- **B adds a caller-controlled input** (the bytes) — fully closed by
  hash + geometry, yet it is new surface and new transport (the SDK/API/
  mobile intent → builder pipeline would have to carry 1.5–5 KB per
  call, and its encoding becomes consensus-visible under the
  production-byte rule).
- **C adds none.** The bytes it reuses are the consensus-verified redeem
  of the token input (P2SH-bound), already proven by
  `readInputStateWithTemplate` (SOURCE-VERIFIED in the silverscript
  compiler: blake2b check + `ScriptPubKeyP2SHFromRedeemScript` equality
  against the input's actual SPK), then re-hash-verified by
  `validateOutputStateWithTemplate` at each use (defense in depth). A
  short/foreign/non-P2SH token input fails closed before any state is
  trusted.
- The explicit up-front gate in B costs ~6,300 units at bound 2 and is
  redundant with the builtins' per-use verification (B-lean proves the
  same refusals); C keeps the builtins' checks and needs no gate.

## 5. Descriptor / schema impact: NONE

`policyvault-asset-descriptor/1` already pins exactly what C needs:
`tokenCovenantId`, `acceptedTransferTemplates[].templateVmHashBlake2b256`
(required, in-VM identity), `prefixLen`, `suffixLen`, `stateLayout`
(closed enum; the encoded state length — 46 B for `kcc20-state/1` — is a
deterministic core derivation from the layout, not a descriptor field),
plus the optional `templateKcc1HashBlake3` interoperability identity.
Template carriage is an execution/encoding concern of the controller;
no transport/witness detail enters the descriptor.

## 7. Decision criteria and recommendation

1. Security properties VM-PROVEN for the candidate — **yes** (B, B-lean,
   C; C with no caller-controlled bytes).
2. No new authority/substitution path — **C: none; B: one, closed**.
3. No hash-convention ambiguity — **none**; geometry pinning is
   mandatory (split-shift finding) and already in the descriptor.
4. No unacceptable standardness/mempool problem — **none**; C improves
   admission cost the most.
5. Improvement meaningful enough to justify complexity — **C: −40 %
   compute, −65…−75 % bytes/fee, with LESS interface complexity than B
   and the same as A**. The improvement is not marginal.

**Recommendation: FREEZE WITH variant C — TRANSACTION-DERIVED VERIFIED
TEMPLATE CARRIAGE** (the owner's canonical name; not "argument-supplied",
which denotes variant B). Retain B-lean as the proven fallback only if a
future upstream builtin change ever removes the input-side P2SH proof.
Retain A only as the reference for the D1 evidence.

**Freeze readiness:** the sole blocking decision is resolved; the
D1 accepted-risk items stay recorded as accepted risks (issuer-power
corroboration depth; estimator/mass-based fee budgeting — now with
measured production numbers; live-testnet token proof deferred per the
