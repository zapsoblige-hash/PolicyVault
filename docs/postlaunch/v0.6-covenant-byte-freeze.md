**Reviewer verdict: FREEZE-NOT-FALSIFIED.** An independent adversarial
reviewer (separate agent, own harness copied from `v6_production.rs`, new

principal, redirects proceeds or the protocol fee, breaks token/KAS

reproduced (zero-period leaf ACCEPTED; `periodLengthDaa 1` control →
`UnsatisfiedLockTime 5001 > 5000`); the suite is kept as a permanent hostile
layer of the VM suite.

Refuted (each a real-engine refusal): fee/proceeds index substitution into
covenant outputs, out-of-range and role-swapped indices; rollover claims with a
lockTime below the new start (`UnsatisfiedLockTime`); `periodsElapsed` out of
bounds; agent/recipient co-path malleability (stray path bits, non-32-multiple
siblings, depth 13/17, duplicate siblings, truncation); token-note output
order swaps and claimed-struct swaps; `destScheme` 0x01/0x03/0xff; type-A leaf
with a non-zero `destIdentity`; `directionMask` 0/4/5/6/−1; zero/negative
amounts and bounds; protocol fee above max / absorbing the proceeds; a second
controller input (with or without a second continuation); reserve value routed
to an attacker output; `ownerControl` selectors 6/7/−1/i32::MAX and every
cross-selector rider; `ownerRecover` overpay/underpay/wrong key/covenant-typed
payout/two token inputs; swap-leaf substitution inside the same tree; owner

**Confirmed findings (none falsify the delegate-facing boundary):**

- **F1 (MEDIUM, defense-in-depth; inherited verbatim from frozen v0.3–v0.5;
  owner-committed leaf only; NOT delegate-exploitable):** the covenant has no
  `periodLengthDaa > 0` check. With `periodLengthDaa == 0`, `newStart ==
  periodStartDaa` for any `periodsElapsed ∈ [1,1000]`, so the period counters
  reset without time passing and the successor leaf carries the same start —
  the PERIOD budget is vacuous (per-transaction caps stay enforced). Engine
  evidence: `adv_h2b_zero_period_length_disables_both_budgets` /
  `adv_h14_zero_period_length_controls` (ACCEPTED with exhausted counters;
  `periodsElapsed 0` → refused; `periodLengthDaa 1` → `UnsatisfiedLockTime`).
  Enforcement today: the shared-core leaf normalizers refuse a non-positive
  period for every generation (`core/model/agent-merkle-v4.js`
  `parsePositiveSompi`, `agent-merkle-v5.js` / `agent-merkle-v6.js`

  security-claims row 4 is split accordingly (per-transaction caps PROVEN;
  period budgets PROVEN conditional on `periodLengthDaa > 0`, an

- **F2 (LOW):** fee-reserve consumption is bounded per transaction

## 5. Limitations (prominent, carried unchanged from the readiness record)

1. **Fixture venue only.** The venue profile describes the PolicyVault pool
   FIXTURE. **No real DEX venue is supported.** KaspaKaha / KRON / any real
   venue needs its own reviewed `policyvault-swap-venue-profile/1` (template
   hash, state layout, fee arithmetic) and reopened VM + production-byte +
   testnet proofs.
2. **No mainnet swap claim.** Every swap proof is testnet-10 with test
   assets.
3. **`deadlineDaa` is a pre-sign authorization-freshness boundary enforced
   by the shared core and finalizer, NOT a consensus upper-bound expiry**
   (Kaspa lockTime is a lower bound only). The transaction-level kill
   switches are the exact pool-outpoint and controller-outpoint bindings
   (a signed swap is consensus-valid only while both remain unspent — the
   honest residual; verify → sign → broadcast immediately; no signed swap is
   stored).
4. **BUY requires the documented position/merge model**: the controller
   must already hold a token position (deposit ≥ 1 atomic unit first).
5. **Measured transaction cost is material for small swaps**: the 24,920 B
   redeem gives a flat ≈ 0.0816 KAS relay-floor fee; not economically viable
   below ~10 KAS, marginal 10–50 KAS, viable from ~50 KAS
   (`v0.6-economic-viability.md`); KIP-9 storage mass makes bps-sized
   protocol-fee outputs invalid below ~50 KAS unless padded (builder-guarded).
6. Principal exits only via SELL outcomes or `ownerRecover`; no owner
   principal-withdraw selector.
7. v0.6-labelled manifests exist for swaps only; spend/owner/recover on a
   v0.6 controller are verified by the builder's frozen bytes (an
   application-integration gap, tracked on the shared-core lane).
8. Owner paths (`ownerControl`, `ownerRecover`) verify the owner's signature
   without an in-covenant hash-type gate (same as frozen v0.5/v0.4.1); the
   SIGHASH_ALL discipline for the single owner is signer/SDK policy. The
   agent paths (spend / sell / buy) DO gate SIGHASH_ALL in-covenant. The
   organizational root (v0.7) gates every counted owner signature
   in-covenant.
9. **Internal review only.** Internal reread + independent adversarial
   agent review (never described as an audit).
