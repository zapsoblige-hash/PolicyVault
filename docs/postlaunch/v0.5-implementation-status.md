## Open risks / accepted items

1. **Reference-program scope**: the kcc20/1 adapter supports token
   families whose accepted template is the vendored KCC20 reference program
   at a family bound ≤ 15. Issuer programs with other bytes are refused
   (UNSUPPORTED_TOKEN_PROGRAM) — correct fail-closed behaviour, but a
   product limitation until per-program adapters exist.
2. **Recipient scheme**: v0.5 authorizes p2pk recipients only (leaf
   scheme byte 0x00); p2sh/covenant-id recipients fail closed.
3. **No approval tier in the token controller** (bounded exposure via
   per-agent caps/budgets); adding M-of-N approvals is a later version.
4. **KCC-0001 BLAKE3 identity** is carried as opaque interoperability data
   (no BLAKE3 in the core) — reported NOT_AVAILABLE, never inferred.
5. **Fees** are transient-mass-dominated (~0.024 KAS/spend at the default
   floor) — the node-configurable floor governs; tooling budgets from mass.
6. (closed 2026-09-02) Live testnet token proof and the deposit builder are DONE; see the freeze record.
