## Purpose and boundary

One v0.5 instance per (vault, accepted asset descriptor, accepted
template). It OWNS a KCC20 token position via the KCC-0002 covenant-id/v1
owner scheme and authorizes delegated token spends under TOKEN-denominated
per-agent policy. Its own KAS is exclusively a fee reserve. Security
boundary: Kaspa consensus — every rule below holds against a holder of a
legitimate agent key submitting transactions directly to a node.

## Mutable state (5 fields, 93 bytes in-script)

`boundVaultId` (= vaultId), `feeReserve` (KAS sompi), `paused` (0/1),
`agentRoot` (token-agent Merkle root), `policyNonce`. Token amounts are
NEVER controller state — they live in the token UTXO the instance owns.

## Token-agent policy leaf (125-byte preimage; domain `0x50563501`)

```
sha256(0x50563501 || agentPk(32) || num8(tokenMaxPerSpend) ||
       num8(tokenPeriodBudget) || num8(periodLengthDaa) ||
       num8(periodStartDaa) || num8(tokenPeriodSpent) ||
       num8(agentMaxFeePerTx) || num8(agentMaxCarryKas) ||
       agentRecipientRoot(32) || 0x00)
```
`num8` = 8-byte little-endian. Trailing byte = recipient scheme (0x00 =
p2pk, the only scheme v0.5 supports). Two domains inside one leaf, never
mixed: `tokenMaxPerSpend/tokenPeriodBudget/tokenPeriodSpent` are atomic
token units (i64-bounded); `agentMaxFeePerTx/agentMaxCarryKas` are sompi.
Agent tree depth ≤ 12 (single-leaf co-path fold, v0.4 mechanism);
recipient leaf = `sha256(0x50563301 || recipientPk)` (v0.3), depth ≤ 16.
Preimage lengths 125/36/64 are pairwise distinct.

## Entrypoints

### `tokenAgentSpend(prevState, newState, selfNew, recipientNew, agentPk, tokenMaxPerSpend, tokenPeriodBudget, periodLengthDaa, periodStartDaa, tokenPeriodSpent, agentMaxFeePerTx, agentMaxCarryKas, agentRecipientRoot, policySiblings, policyPathBits, periodsElapsed, recipientPk, recipientSiblings, recipientPathBits, agentSig)`

1. `paused == 0`; `checkSig(agentSig, agentPk)` — the LEAF is the sole key→policy authority.
2. **BINDING A** — `OpCovInputCount(tokenCovenantId) == 1`, `OpCovOutputCount == 2`; `tokIn = OpCovInputIdx(tokenCovenantId, 0)`; **family isolation**: every input other than this covenant and `tokIn` has a zero covenant id (≤ 8 inputs) — no other covenant family (including another asset deposited to this controller's id) can be authorized by the controller's presence.
3. **BINDING B — TRANSACTION-DERIVED VERIFIED TEMPLATE CARRIAGE**: `readInputStateWithTemplate(tokIn, prefixLen, suffixLen, templateVmHash)` proves the token input's revealed redeem (hash + P2SH) BEFORE its state is trusted; the proven prefix/suffix are then sliced out of that input's signature script by pinned geometry (`OpTxInputScriptSigSubstr`) and used to reconstruct both continuation outputs (`validateOutputStateWithTemplate`, which re-verifies the hash at use). Template bytes are never baked into this redeem and never caller-supplied.
4. Ownership: `prevTok.owner == OpInputCovenantId(self)`, scheme covenant-id, not minter; `selfNew` same owner/scheme, not minter, `!= recipientPk`; `recipientNew.owner == recipientPk`, scheme p2pk, not minter.
5. TOKEN domain: `spend = recipientNew.amount > 0`; `selfNew.amount >= 0`; `selfNew.amount == prevTok.amount − spend` (exact conservation); leaf membership under `prevState.agentRoot`; `spend ≤ tokenMaxPerSpend`; period accounting (`periodsElapsed ≤ 1000`; rollover requires `tx.time ≥ newStart` and resets spent); `newSpent ≤ tokenPeriodBudget`; `newState.agentRoot ==` fold of the advanced leaf; recipient membership under the leaf's recipient root.
6. KAS domain: `selfOut.value + recipientOut.value ≥ tokIn.value` (family KAS never leaks); `recipientOut.value ≤ agentMaxCarryKas`; `reserveConsumed = prev.feeReserve − new.feeReserve ∈ [0, agentMaxFeePerTx]`, `≤ txFee()` (≤ 8 in / ≤ 8 out); successor value `== newState.feeReserve`.
7. Global continuity: `boundVaultId`, `paused`, `policyNonce` preserved; `descriptorHash != 0`.

### `ownerControl(prevState, newState, opSelector, ownerSig)`

Single owner `checkSig`; `opSelector ∈ [0,3]`, exhaustive mutually
exclusive dispatch: 0 setAgentRoot (nonce +1, reserve/paused preserved),
1 topUpReserve (reserve strictly increases, root/paused/nonce preserved),
2 pause (0→1), 3 unpause (1→0). NO covenant input other than this one may
be present (tokens never move under owner control). Successor value `==
newState.feeReserve`.

### `ownerRecover(prevState, nextStates[], ownerSig, recipientNew)` — terminal

`nextStates.length == 0`; output 0 `== P2PK(owner)` with value `==
prevState.feeReserve`; at most one token-family input: if present, exactly
one family output, the input template proven as above, and the ENTIRE
amount moves to `owner` under the p2pk scheme via a template-verified
continuation (tokens are never stranded under a dissolved covenant id);
no other covenant family present in either case.

## Static standardness

Static P2SH sig-ops of the controller redeem: 3 (`tokenAgentSpend`,
`ownerControl`, `ownerRecover`) ≤ 15. The TOKEN input's static sig-ops
equal the accepted template's family bound (one `checkSig` per unrolled
KCC20 iteration): templates with bound > 15 are non-standard and MUST fail
the onboarding gate (enforced by `core/assets` `templateStandardness`).
